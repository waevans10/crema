# Crema 1.2.0 — Dial-in workflow and reliability

Crema 1.2.0 adds self-guided dial-in guidance, structured experiment decisions,
and canonical community dataset exports. It also fixes ten findings from the
[November audit](../audits/2026-11-17-ponytail-audit.md).

## Highlights

- Use local guidance without paying for an AI review; record whether an
  experiment helped and choose to keep, revert, or continue testing.
- Expired reviews no longer block ingestion when experiments reference them.
- Reviews retry already-ingested shots after a failed AI call or an ingest-only run.
- CLI and web enforce the same cup-rating and stop-change approval rules.
- Atomic draft claims prevent duplicate machine writes; refinement and discard
  cannot overwrite an in-progress push.
- Version-2 exports pass through collection and import with consent evidence.
  Snapshot replacement removes stale dataset rows instead of duplicating shots.
- Gaggiuino shots join experiments and export the correct machine identity and
  normalized measurements.
- Unrated experiment baselines are rejected before an existing run is closed.
- Unused Jinja2/MarkupSafe dependencies were removed. Worker tooling was updated
  to address reported npm advisories, and contract/type checks now run in CI.

## Upgrading

Back up the SQLite database, update to `v1.2.0`, run `uv sync --frozen`, and
restart your Crema service. Python 3.13+ is still required. Existing databases use
the existing additive migration path; no database reset is required.

Rate the source cup before drafting or pushing a review-based profile update.
New-bean starting profiles have no source cup and remain exempt. If a draft
changes stop conditions, review those changes before using the web checkbox or:

```bash
crema push EDIT_ID --acknowledge-stops
```

A push interrupted after claiming the draft remains `pushing`; an uncertain
response becomes `unknown`. Check the machine's saved profiles before creating
another draft. These states cannot be automatically retried.

For community-pool operators, deploy the updated Worker before enabling
version-2 client uploads. New version-1 submissions are rejected explicitly;
existing R2 objects are not modified. Keep legacy data separately and do not
infer version-2 consent. Imports replace a participant's current snapshot;
process submissions in collection order and retain raw objects for history.
See [the Worker guide](../../share-worker/README.md).

Worker development requires Node 22.18+; CI uses Node 24.

## Validation and limits

- 75 Python tests pass, including 13 new regression cases.
- 3 offline Worker contract tests pass, including real export → collector → import.
- TypeScript checking and Wrangler's deployment dry-run pass.
- npm reported zero advisories after the Worker tooling update.

Live GaggiMate/Gaggiuino hardware, paid AI calls, and production Worker deployment
were not exercised. The existing Starlette TestClient deprecation warning remains.
This GitHub release does not deploy the Worker or update running installations.
